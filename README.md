# Proctolog

CLI-утилита, которая периодически делает скриншот экрана и отправляет его вместе
с текстовым промптом в RouterAI API.

По умолчанию используется:

- API base URL: `https://routerai.ru/api/v1`
- endpoint: `/chat/completions`
- model: `x-ai/grok-4.3`
- API key env: `ROUTERAI_API_KEY`

## Важное ограничение

Утилита не дописывает сообщения в веб-чат ChatGPT. Она отправляет запросы в
RouterAI API и пишет ответы локально в `transcript.md` и `events.jsonl`.

RouterAI Chat Completions API не является "чатом" в браузере: чтобы сохранять
контекст между запусками, утилита хранит последние текстовые ответы локально и
передаёт их в следующий запрос как краткий контекст. Сами прошлые скриншоты не
переотправляются, чтобы не раздувать стоимость и размер запроса.

Документация RouterAI:

- Quickstart: https://routerai.ru/docs/guides/overview/quickstart
- Authentication: https://routerai.ru/docs/guides/overview/authentication
- Image input: https://routerai.ru/docs/guides/overview/multimodal/images
- Multimodal overview: https://routerai.ru/docs/guides/overview/multimodal/overview

## Установка

```sh
cd ~/Projects/proc-util
scripts/bootstrap
source .venv/bin/activate
proc-util --help
```

Проект не требует внешних Python-зависимостей. `scripts/bootstrap` создаёт
`.venv` и локальную команду `.venv/bin/proc-util` без обращения к PyPI.

Укажите API-ключ RouterAI:

```sh
export ROUTERAI_API_KEY="..."
```

На macOS терминалу, из которого запускается утилита, нужен доступ Screen
Recording в System Settings -> Privacy & Security -> Screen Recording.

Перед постоянным запуском учитывайте, что скриншоты могут содержать приватные
данные и будут отправляться во внешний API. Интервал 10 секунд также может
быстро расходовать бюджет API.

## Конфигурация

Создать конфиг:

```sh
proc-util init
```

Файл по умолчанию:

```text
~/.config/proc-util/config.json
```

Если конфиг уже был создан для OpenAI-версии, пересоздайте его:

```sh
proc-util init --force
```

Основные параметры:

```json
{
  "api_base_url": "https://routerai.ru/api/v1",
  "api_key_env": "ROUTERAI_API_KEY",
  "model": "x-ai/grok-4.3",
  "interval_seconds": 10.0,
  "prompt": "Реши тестовое задание на текущем скриншоте. Если предыдущий скриншот связан с текущим, используй его как дополнительный контекст. В ответе дай краткий итог и конкретный вариант ответа.",
  "system_prompt": "Ты помощник, который решает тестовые задания по скриншотам рабочего стола. Всегда сначала ориентируйся на текущий скриншот. Предыдущий скриншот используй только если он связан с текущим заданием или содержит недостающий контекст. Отвечай кратко, по делу и на русском языке.",
  "detail": "low",
  "history_turns": 3,
  "output_dir": "~/.local/share/proc-util",
  "keep_screenshots": 120
}
```

`history_turns` управляет тем, сколько последних текстовых ответов будет
добавляться в следующий запрос как контекст. Поставьте `0`, если контекст между
запросами не нужен.

Начиная со второго API-запроса утилита прикладывает к запросу два изображения:

1. предыдущий скриншот;
2. текущий скриншот.

Промпт явно сообщает модели порядок изображений и просит использовать предыдущий
скриншот только если он связан с текущим тестовым заданием. Первый запрос после
старта отправляет только текущий скриншот, потому что предыдущего ещё нет.

## Запуск

Один пробный цикл без обращения к API:

```sh
proc-util run --once --dry-run
```

Один реальный цикл:

```sh
proc-util run --once
```

Постоянный мониторинг раз в 10 секунд:

```sh
proc-util run
```

Переопределить промпт и интервал из CLI:

```sh
proc-util run --interval 10 --prompt "Опиши, что сейчас происходит на экране. Отвечай кратко."
```

Переопределить команду скриншота из CLI:

```sh
proc-util run --screenshot-command gnome-screenshot -f "{output}"
```

## Выходные файлы

По умолчанию данные пишутся в:

```text
~/.local/share/proc-util/
```

Там будут:

- `state.json` — последний response id и короткая текстовая история;
- `transcript.md` — человекочитаемый лог ответов;
- `events.jsonl` — структурированный лог;
- `screenshots/` — последние скриншоты.

`state.json` также хранит путь к последнему скриншоту, чтобы следующий запрос мог
отправить пару “предыдущий + текущий”.

## Просмотр с другого устройства

Самый простой вариант — запустить встроенный web-сервер:

```sh
proc-util serve
```

Он напечатает адреса вида:

```text
Local URL: http://127.0.0.1:8765
LAN URL:   http://192.168.1.10:8765
```

Откройте `LAN URL` в браузере на смартфоне. Компьютер и смартфон должны быть в
одной сети Wi-Fi. Страница показывает только последний ответ и автоматически
обновляется каждые 10 секунд.

Кнопка в правом нижнем углу управляет `proc-util run`:

- `Пауза` — сразу прерывает текущий worker с API-запросом и останавливает новые
  скриншоты;
- `Продолжить` — сразу запускает следующий цикл, не дожидаясь остатка интервала.

Локально запрос отменяется через завершение worker-процесса. Если провайдер уже
полностью принял запрос к обработке, он всё равно может быть учтён на стороне API.

Если порт занят:

```sh
proc-util serve --port 8766
```

Если macOS спросит разрешение на входящие подключения для Python/Terminal,
разрешите его для локальной сети.

## Кастомная команда скриншота

По умолчанию на macOS используется:

```sh
/usr/sbin/screencapture -x <output>
```

Для другой системы можно задать `screenshot_command`:

```json
{
  "screenshot_command": ["gnome-screenshot", "-f", "{output}"]
}
```

## Почему не DeepSeek V4 Pro

RouterAI принимает изображения через `image_url` в `/chat/completions`, но
конкретная модель должна поддерживать входные изображения.

`deepseek/deepseek-v4-pro` на странице RouterAI указан как text-only: входящие
данные — только текст, исходящие — только текст. Поэтому он не видит скриншот и
отвечает, что изображение не прикреплено. Для этой утилиты нужна vision-модель,
например `x-ai/grok-4.3`.
